# Decisions

Architecture Decision Records for RepurposeKG. Newest at the bottom. One paragraph each; if it needs more, link a doc.

| # | Date | Decision | Why | Alternatives rejected |
| --- | --- | --- | --- | --- |
| 1 | 2026-10-28 | **Biomedical drug repurposing on a knowledge graph is the project theme.** | It uses a real, large, well-known KG, has a measurable ML task (link prediction), and fits pharma/biotech AI roles in Germany and the user's natural-sciences degree. | German crop-protection KG (too niche; portfolio already agri-heavy); pure RDF/OWL on GovData (little AI); OpenAlex research KG (generic). |
| 2 | 2026-10-28 | **PrimeKG as the only core dataset.** | CC0-labelled, 129k nodes / 4M edges, 10 node types, ships text features for drugs and diseases, used by published repurposing work (TxGNN), so results are comparable. | Hetionet (2017, smaller, kept as stretch cross-check); building our own KG from literature (months of NER work, unverifiable quality). |
| 3 | 2026-10-28 | **Neo4j 5 Community as the graph store; Cypher as the query language.** | Property graph is the most common KG stack in industry job ads; `neo4j-admin database import` loads 4M edges in minutes; full-text index gives entity lookup for free. | RDF triple store + SPARQL (kept as stretch export, task 9); NetworkX only (no query language, no server); Postgres + recursive CTEs (awkward path queries). |
| 4 | 2026-10-28 | **Target task: predict `indication` edges (drug → disease); evaluate on a disease-held-out split plus a random split.** | The disease split asks the real repurposing question ("a disease with no known drugs in training") and stops the model from just memorising drug popularity. Random split is reported for comparison only. | Random split only (inflated numbers); predicting all relation types (diffuse story). |
| 5 | 2026-10-28 | **Models in increasing complexity: popularity → shared-neighbour heuristic → PyKEEN KG embedding (RotatE/ComplEx) → PyG heterogeneous GNN (R-GCN/HGT encoder + DistMult decoder).** | Each step must earn its place against the previous one in the model card; a GNN that loses to a heuristic is reported as such. | GNN only (unfalsifiable); reimplementing TxGNN wholesale (not readable, GPU-heavy). |
| 6 | 2026-10-28 | **CPU-only training on a pruned graph** (drop drug–drug synergy and anatomy expression by default, flag to include them). | Those two relations are 70% of rows and carry little signal for indications; keeps training within the dev VM (8 cores, 31 GB, no GPU) and reproducible by a reviewer. | Rent a GPU (cost, reproducibility). |
| 7 | 2026-10-28 | **Explanations are graph paths, not post-hoc saliency.** For each predicted pair we return the top metapaths (e.g. drug –target→ gene –associated→ disease) ranked by path count and edge-type weights. | Paths are checkable by a domain expert in Neo4j Browser; GNNExplainer-style masks are hard to show and to trust. | GNNExplainer (stretch at most). |
| 8 | 2026-10-28 | **External validation against ClinicalTrials.gov.** Top-k novel predictions are checked for registered trials and compared with random and popularity baselines. | Gives a second, independent signal besides held-out edges; easy to explain in an interview. | No external check; literature co-occurrence via PubMed (noisier, rate limits). |
| 9 | 2026-10-28 | **GraphRAG = entity linking + template Cypher for top intents + guarded text-to-Cypher fallback + answer with cited paths.** | Templates make the demo reliable; the LLM path covers everything else; guards (read-only tx, `EXPLAIN`, label/relation allowlist, forced `LIMIT`, timeout) make it safe; a gold question set measures both. | Vector RAG over node descriptions only (loses the graph); LangChain `GraphCypherQAChain` as a black box (hard to guard and evaluate). |
| 10 | 2026-10-28 | **Anthropic Claude as primary LLM, Ollama as offline fallback, behind one provider interface; LLM tests run on recorded responses.** | Same pattern as ClaimPilot; CI never needs a key. | Single hard-wired provider. |
| 11 | 2026-10-28 | **Predictions are written back into Neo4j as `PREDICTED_INDICATION` relationships with `score`, `rank`, `model_version`.** | Lets Cypher (and the LLM) ask "predicted but not indicated" questions; one source of truth for the API. | Separate parquet served by the API (two stores to keep in sync). |
| 12 | 2026-10-28 | **Backend: FastAPI (Python 3.12, uv). Frontend: Vue 3 + TypeScript + Vite + Cytoscape.js, one route.** | Same languages as the user's other projects; Cytoscape.js is the standard for interactive graph views. | Streamlit (looks like a notebook); React (fine, no reason to switch). |
| 13 | 2026-10-28 | **Non-commercial, research-demo framing.** README and UI state "not medical advice"; DrugBank-derived content is CC BY-NC 4.0. | Honest about data licensing and about what a link-prediction score means. | — |
| 14 | 2026-10-28 | **Work style: one task = one GitHub issue = one branch `task-N-slug` = one PR, with a one-page spec in `docs/specs/` before coding.** | Small reviews; roadmap stays honest. | Big-bang build. |
